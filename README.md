## Zaid Hijazi

Security engineering focused on public, reviewable tools for defensive workflows, web-security controls, evidence handling, and bounded systems.

The work here is intentionally evidence-first: public repositories and technical notes describe the behavior they can support. There are no claims of CVEs, third-party findings, client work, bounty outcomes, or impact that the public record does not demonstrate.

### Selected public work

| Project | Public evidence |
| --- | --- |
| [SOC CaseForge](https://github.com/Z3X-1337/soc-caseforge) | Local-first SOC case workflow for sanitized evidence, timelines, indicators, deterministic detections, and reviewable Markdown/JSON reports. |
| [Security Header Auditor](https://github.com/Z3X-1337/security-header-auditor) | Authorized HTTP response review for selected security headers, redirect behavior, CSP observations, and CI quality thresholds. |
| [Auth Log Analyzer](https://github.com/Z3X-1337/auth-log-analyzer) | OpenSSH authentication-log analysis with explainable JSON and Markdown output for supported events. |
| [IOC Sanitizer](https://github.com/Z3X-1337/ioc-sanitizer) | Local extraction, validation, normalization, defanging, and refanging of supported indicators while retaining original form. |
| [ToxicJoin](https://github.com/Z3X-1337/toxicjoin) | A compositional privacy gate for AI data agents that deterministically allows, rewrites, or blocks proposed SQL before execution. |

### Working themes

- **Web and application control surfaces** — HTTP response policies, authorization boundaries, and precise review language.
- **Evidence-first defensive tooling** — local processing, transparent thresholds, provenance, and analyst-oriented outputs.
- **Bounded systems** — explicit policy, approvals, and deterministic safeguards around actions proposed by an AI system.
